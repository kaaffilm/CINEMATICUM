# CINEMATICUM 0.9.1 candidate — engineering comparison and implementation audit

**Status: a substantive upgrade to CINEMATICUM's own editor; full parity with the listed applications remains unimplemented.** This audit records inspected source/interfaces, concrete changes, reproducible acceptance and unresolved requirements. It does not assign a misleading completion percentage or present an installed external program as an implemented CINEMATICUM feature.

The user requirement is one audiovisual authoring application with one project, timeline, media inventory, undo history and output pipeline. CINEMATICUM's controls author the data. FFmpeg and Blender are headless processing engines; no third-party editor interface is opened or embedded. A backend integration counts only for the operations actually exposed, preserved and executed.

The current source implements selected-source PCM playback, measured affine/projective tracking and 16-bit SDR movie processing. Their native acceptance, one complete regression run on the same frozen source, verified replacement installation and publication are separate release gates. Earlier Metal and reduced Wan executions remain evidence only for their recorded source and settings. In particular, the earlier 515-test result does not certify these newer changes. [Verification 0.9](VERIFICATION_0_9.md) retains historical execution; [verification 0.9.1](VERIFICATION_0_9_1.md) records current gates and the [unfinished-work register](UNFINISHED_0_9.md) retains the broader requirements. This document describes candidate source and does not assert a completed 0.9.1 release.

## Concrete changes in this build

### 1. Exact time and audio boundaries

`timebase.py` stores a reduced integer ratio and derives the convenience FPS number. The renderer carries the ratio through source conform, timestamp units, canvas generation, encoding and Blender image sequences. Timeline positions are integer frames; source in-points may be fractional project frames. All 48 kHz audio placements use absolute sample boundaries, so successive 29.97/59.94 cuts do not accumulate independently rounded sample errors.

This exposed and fixed two export defects: a redundant output picture limit truncated the limiter's audio tail, and MOV's previous movie timescale rounded audio edit duration too coarsely. Tests examine packet timestamps, decoded pictures and PCM, including reverse, fractional trims, held/eased gain and many cuts. NDF remains the default display; the Sequences controls now select DF numbering at exact 30000/1001 or 60000/1001. Display selection does not alter frame or audio timing.

Decoded split comparisons also exposed timestamp truncation changing half-frame selection after a fractional source split. A bounded frame-aligned conform clock and explicit retimed timestamp rounding preserve the selected pictures across cuts. Permanent regression coverage compares every decoded frame in 48 combinations of container timestamps, rate, speed and direction, each split at three positions. The paused-frame cache version changes with this correction.

### 2. Animated image processing and shape geometry

Compositor nodes now store separate animation channels. Grade, blur, chroma tolerance/blend, merge opacity and mask placement/feather/geometry evaluate at the clip's preserved animation-domain frame. A property edit cannot silently key unrelated channels. Polygon and cubic Bézier path keys preserve consistent topology; cubic split/remove updates all keys, and completed point gestures use one undo checkpoint. Cubic anchors retain independent incoming/outgoing handles and point feather. Parameters, paused PNGs and movie export evaluate the same saved data.

The graph now contains one primary clip source and up to eight independent project-media nodes within its 32-node limit. Each additional source references an owned asset ID and specifies its source in-point, duration, signed animation-domain offset and transparent/hold policy. Actual pictures feed the saved connections and ordered merges; source audio is not implicitly mixed. Trims/splits preserve the animation domain. The same graph feeds paused-frame PNGs and movie export. Node counts, animation keys and working pixels remain bounded; nested compositions, deep/multiview/arbitrary channels and a plugin host remain absent.

Cubic masks contain 2–32 anchors with point-feather scales 0–4 and at most 64 path keys. NumPy rasterizes the authored curves with adaptive 0.125-pixel flattening and 2×2 sampling into 16-bit coverage; output hashes and request identities are verified before composition. Static and animated coverage share the paused/export path. The isolated worker has a 4 GiB output bound and cancellation; this is not an unrestricted realtime roto engine. Single closed SVG M/L/H/V/C/S/Q/T/Z paths can be imported/exported, with own metadata retaining feather. General SVG documents, transforms, resources, arcs, roto hierarchy and paint remain absent.

Grade, curves, blur, sharpen, key and calibrated-lens nodes expose optional invertible alpha-mask inputs. Graph-cycle/resource checks include those dependencies, and rendering blends associated color and alpha. Animation adds monotone cubic progress tangents bounded to 0–3; arbitrary overshooting curves remain absent. Save/Import graph exchanges bounded JSON with current-project media IDs, not packaged external assets. `test_roto_ui_macos.py` passed 26 native checks; exact cases and artifacts are listed in verification 0.9.

A calibrated lens node adds actual static Brown undistort/redistort processing with explicit normalized intrinsics and five distortion coefficients. Compatible base camera intrinsics can be copied from the scene. A whole-canvas contraction bound of `q ≤ 0.45` rejects folding/strong models; two lens nodes and 2,073,600 nonidentity canvas pixels are the current limits. An owned, cancellable worker generates six verified 16-bit sampling maps. Bilinear RGBA remapping preserves premultiplied edges and uses transparent out-of-frame samples. Identity is an exact bypass. Lensfun profile conversion, fisheye/anamorphic/rational models, auto-calibration and animated coefficients remain missing.

Extending a clip enlarges the editable animation domain to include the new visible interval without inserting keys or moving existing trajectories. Audio fade endpoints retain their independent original domain.

### 3. Measured tracking that changes the actual output

The original point tracker decodes actual conformed source pictures and measures the selected patch with FFmpeg correlation. Its 384-pixel analysis edge and 480-frame limit remain distinct from the new planar worker. Receipts preserve source identity, rational clock, source-time mapping, positions, visibility and confidence. Missing matches remain gaps; the code does not invent trajectories.

The planar worker executes OpenCV pyramidal Lucas–Kanade flow, rejects inconsistent forward/backward and photometric matches, and estimates affine or projective motion with RANSAC. The own Track controls select four image corners and the desired model. Limits are 240 frames and a 640-pixel analysis edge; once the measured surface is lost, the worker does not silently reacquire a different object. The source is hashed before and after measurement, and rendered dependencies are checked again before processing.

Applying the measurement creates independent source-bound stabilization or an image corner pin. The compositor evaluates the actual matrix in paused and movie output, with associated-alpha bilinear sampling in both ordinary RGBA and the high16 path. Paused edit mode requests the processed frame whenever a planar motion channel is present; browser source playback is not used as an exact warp preview. A pin on an already stabilized background composes with the applied stabilization so the image stays on the visible surface. The warp is bounded to 2,073,600 canvas pixels. Existing position, scale, rotation, opacity, sound and overlay media remain authored separately.

Timing and dependency edits have explicit behavior. Moving the tracked clip on the timeline moves its dependent pin once while preserving the valid source-bound samples. Source slips, trims, duration/speed/reverse/rate changes, source replacement/deletion, independently moved pins, invalid track ordering or changes to the driving transform/stabilization mark the derived motion stale. The application preserves the overlay clip, imported media, authored values and original measurement, shows a warning, and records invalidation/remapping in the same undo step. Stale stabilization is bypassed; a stale pin is transparent in preview. Movie export rejects stale motion until it is remeasured or explicitly cleared. Save/reopen retains the stale state; ordinary undo restores the prior valid state.

`test_planar_tracking.py` checks projective geometry, binding edits, stored sequences, transparent stale pins and export refusal, source rehashing, and independently decoded stabilized/corner-pinned pixels. Its real OpenCV inference cases require a verified worker; missing OpenCV is a reported skip. Native-08 passed 10/10 checks in 9.463 seconds, including seven actual control stages: exact project selection, four-corner measurement, stabilization/pin application, undo/redo, timing invalidation/remapping, save/reopen/processed-frame review, and ProRes export. All 12 frames had actual visible OpenCV measurements. Independent decoding found the pinned image at centroid (80.5, 64.0) in both first and last frames; the actual ProRes movie was 268,926 bytes. The native control sequence took 6.142 seconds and reported no browser errors. Full source/output hashes and receipts belong in [verification 0.9.1](VERIFICATION_0_9_1.md). Automatic re-identification, learned tracking, rolling-shutter/lens estimation and semantic segmentation remain missing.

The [final-native-01 rerun](verification/0.9.1/final-native-01/planar/result.json) passed 10/10 in 7.342 seconds. After the explicit worker-bytecode correction, the [bundle-fixed rerun](verification/0.9.1/bundle-fixed-planar/result.json) passed 10/10 in 10.282 seconds through all seven native stages with real OpenCV measurement and independent movie decoding. Stable pin centers and movie bytes/hash matched the earlier output. Install-03 passed for the corrected source; its full private receipt is now collected/hash-verified. Canonical launch-02 passed 16/16 and final source reconciliation passed 9/9 against published `81827cf`.

Earlier native attempts exposed and fixed dialog DOM serialization and the missing edit-mode processed-frame trigger; the harness also now selects its exact fixture project and tests explicit stale-status markers. Native-07 reached export but exceeded its 12-second export deadline while Wan inference was active. Native-08 ran after generation stopped and passed. That sequence does not establish sustained concurrent throughput. The harness now retains its isolated workspace, helper stdout/stderr, job state before/after owned shutdown, worker files, measurement and partial stage diagnostics on failure; its export deadline is bounded to 60 seconds within a 120-second control sequence.

The optional managed tracking interpreter is `~/Library/Application Support/CINEMATICUM/Tracking/py313-v1/bin/python`, with locked NumPy 2.3.5 and opencv-python-headless 4.11.0.86. `CINEMATICUM_TRACKING_PYTHON` can select a compatible verified interpreter. App replacement preserves this external runtime; the standard-library server delegates actual array/vision work to it.

### 4. Geometry that survives viewport, render and scene replay

The OBJ/MTL path parses selected text into bounded indexed meshes, triangulates concave simple faces, preserves UV/normal corners, partitions materials, and records actual source hashes. It never follows embedded filesystem references. The editor displays and ray-selects the actual geometry and appends an import as one undoable scene edit.

The authored model retains ordered control polygons, a canonical geometry hash, separate source provenance, live modifier recipes and actual evaluated geometry. Own vertex/face modes support exact selection, local coordinates and move handles. Extrude, connected subdivide and delete change actual cage topology. Vertex-only deformation preserves UV seams; topology-changing operations explicitly invalidate UVs for reprojection. One accepted worker candidate enters shared undo once.

Eight modifier types execute in Blender: Mirror, Bevel, Subdivision, Solidify, Array, Decimate, Smooth and Simple Deform. Ordered parameter/enable/reorder/remove/refresh/apply controls retain the base cage and live stack in `.blend`. Before rendering, Blender reevaluates and compares actual engine version, geometry, normals and UVs against the saved evaluation. Bounds include 10,000 cage vertices/faces, 60,000 corners, 512 selected elements, eight modifiers, subdivision through three levels and Array counts through 64. Expansion estimates and the shared 5 MiB cage/evaluation budget still apply; a modeling operation uses one owned 45-second worker.

Object parenting now composes exact affine transforms, including inherited nonuniform scale and local pose animation. Own controls, picking, normals and world-space moves share that transform contract; the retained `.blend` has real parent links and local keys. Cycles/missing references and more than 24 levels reject. Changing parent keeps local values, so it changes the inherited world pose. Camera/light parenting, constraints and keep-world reparenting are not implemented.

The UV editor supports box/planar/individual-face projection, actual Blender smart unwrap, selected-face seam separation, grid-based island packing and exact/drag/rotate/mirror/scale coordinate edits. UV corners and seams survive quad/n-gon Blender cages. Packing gives each connected island a separate cell with margin and preserves individual aspect; it does not optimize arbitrary packing or equalize density. Texture painting, image shader assignment and a material graph are not implemented.

`test_scene_authoring_blender.py` passed 19 native backend checks across hierarchy, actual UV/modifier replay and device configuration, including retained CPU-rendered geometry. All eight `test_scene_authoring_ui_macos.py` stages passed through actual controls. An earlier short Metal pixel harness timed out, but a later normal owned app job completed in 82.430497 seconds. Independent verification passed 18/18 checks in 6.694 seconds on actual pixels, retained scene and Metal device receipt without CPU fallback. This was one 192 × 128 frame at four samples without denoising; larger scenes and other GPU backends remain unverified. Edge modeling, rigs, sculpting, geometry nodes, simulation and reconstruction remain unimplemented.

### 5. Interchange with explicit fidelity and an undoable application step

The bounded OTIO exporter writes picture/audio tracks, gaps, cuts and actual media references. Companion audio tracks avoid ambiguous embedded-sound behavior. The importer resolves already-imported media using verified SHA-256 or explicit selections; it never follows arbitrary document URLs. The preview shows the candidate edit and warnings before one undoable replacement. It does not autosave.

Private authoring metadata can reconstruct an unchanged CINEMATICUM roundtrip. A digest of the public edit detects external changes; private effects are not allowed to override edited public timing. This is change detection, not authentication. Bounded nested Stack/Track exchange now carries nested source ranges, separate picture/audio roles and explicit/trailing/all-gap durations. Public-only imports create editable sequence views and retain prior destination sequences. Unchanged private roundtrips restore active/inactive sequence libraries only after byte identity and regenerated public timing/structure agree. OTIO export rejects retime/reverse, same-track overlaps and transitions; trimmed Tracks/top-level Stacks, disabled nested items and general plugin schemas remain unsupported. Effects, captions and mixer gains remain private metadata. Tests use decoded picture/PCM, with an official OTIO reader only where its optional test dependency is available; its absence is a skip. General AAF/XML/native-project conversion remains missing.

Protocol fixtures establish those branches separately from actual model execution.

### 7. Calibrated camera interchange

The fSpy reader validates its real binary header and JSON camera records. COLMAP import reads the explicitly selected camera/image text pair, verifies camera IDs/quaternions and preserves pinhole intrinsics. Both map into the own camera model with explicit world-axis conversion and translation scale. Roll, image principal point and `fx/fy` survive; incompatible aspect ratio, unsupported distortion and invalid geometry reject before application. Camera selection is reviewed and applied once through project undo; prior camera animation is explicitly replaced.

The scene viewport and retained Blender camera use the same projection contract. Acceptance compares source equations to WebGL projected points and independently reopens the retained `.blend` to check actual Blender projection. This imports a solved camera; it does not perform COLMAP reconstruction or fSpy vanishing-line solving. The camera reader still rejects unsupported distorted COLMAP camera models. The new separate calibrated-lens compositor node processes footage using explicitly supplied Brown calibration; it does not turn import into a calibration or reconstruction solve.

### 8. Physical camera, material and transport controls

The saved scene now carries sensor height, authoritative vertical FOV, derived focal length, roll/shifts/focal ratio, focus distance/f-stop and aperture shape. Pose channels preserve the lens parameters at each integer frame; incompatible redundant lens values reject. Cycles receives the actual DOF/aperture settings, Principled transmission/IOR/emission and bounded bounce/denoising/seed parameters. Emission color is converted from authored display RGB to scene-linear values.

The own viewport supplies editable geometry and approximate material feedback. Compute device selection retains CPU as the default and supports explicit Metal/CUDA/OptiX/HIP/oneAPI requests. The executing Blender must enumerate a matching available device or the job fails; no silent CPU fallback occurs. Recipes/receipts record the choice and actual devices, while portable `.blend` files retain the GPU flag rather than machine-specific preferences. Native acceptance checks retained camera/material/integrator properties and rendered sharp/defocused CPU pixels. Actual Metal picture rendering now has the bounded 18-check proof described above; other GPU backends have not been verified on hardware. This does not implement Mitsuba differentiation, pbrt spectral transport, optical prescription optimization or Gaffer's general scene graph.

### 9. A real input color stage and owned LUTs

A float RGBA stage decodes declared source transfer, applies primary conversion and Bradford white adaptation, then encodes Rec.709. Supported inputs are Rec.709/sRGB/linear/LogC3 EI800 with Rec.709/Rec.2020/ACEScg/ARRI Wide Gamut 3 primaries. A strict Cube reader supports single 1D/3D tables with independent per-channel domains, plus combined 1D-shaper/3D tables with separate scalar INPUT_RANGE declarations. A combined shaper always uses linear interpolation before the selected nearest/trilinear/tetrahedral 3D interpolation. Ambiguous shared domains are rejected. The project stores canonical UTF-8 tables by actual SHA-256, with missing/tampered tables rejected at validation.

Investigation exposed FFmpeg Cube-domain handling that was insufficient for nonzero minima. The compiler explicitly normalizes each channel and feeds a unit-domain table. Tests exercise nonzero/unequal domains, combined stage ranges and sequential evaluation, all tetrahedral regions, alpha, transfer reference values and literal filter paths. Integration tests decode the actual current-frame PNG and exported movie and verify that the stage feeds the compositor. The UI imports real files, applies through one undo entry, saves and reloads.

Float values survive this input stage; the movie compositor and delivery remain SDR. Its ACEScg primary conversion is distinct from the actual OCIO display-view transforms now available in the separate still-image worker.

The optional worker executes real builtin-config OpenColorIO source-to-scene-linear and display/view transforms. RAW development uses rawpy/LibRaw on preserved SHA-addressed camera originals, exposing demosaic, white balance, highlights and half-size controls. HDR merging combines 2–16 aligned static-scene stills with explicit shutter times and a known response. It does not fit a response curve, align frames or remove ghosts.

Each successful operation retains a float32 ZIP RGBA `linear.exr`, a separately encoded 16-bit sRGB `display.png` and a receipt binding the recipe, actual source/config/runtime identity and output hashes.
